1. VPN이란 무엇인가? (What is a VPN?)

VPN(Virtual Private Network, 가상 사설망)은 공개 인터넷 위에 암호화된 터널을 만들어 마치 같은 사설 네트워크에 있는 것처럼 통신할 수 있게 해주는 기술입니다. 원격 근무, 지사 연결, 보안 접속 등에 광범위하게 사용됩니다.

[사용자 A] ──암호화 터널── [인터넷] ──암호화 터널── [회사 서버] ↑ VPN 서버(게이트웨이)
핵심 개념: VPN의 목적은 기밀성(Confidentiality), 무결성(Integrity), 그리고 접근 제어(Access Control)입니다.

2. 전통적인 VPN의 작동 방식 (How Traditional VPNs Work)

2-1. Hub-and-Spoke (허브 앤 스포크) 아키텍처

전통적인 기업 VPN(OpenVPN, IPsec/IKEv2, Cisco AnyConnect 등)은 중앙 VPN 서버(게이트웨이)를 허브(Hub)로 두고, 각 클라이언트가 스포크(Spoke)처럼 연결되는 구조입니다.

[직원 A] ──────────────→ [VPN 서버/게이트웨이] [직원 B] ──────────────→ [VPN 서버/게이트웨이] [지사 C] ──────────────→ [VPN 서버/게이트웨이] ↓ [내부 네트워크 리소스]

모든 트래픽이 중앙 게이트웨이를 경유(hairpinning)하므로, 두 직원이 서로 통신하더라도 반드시 서버를 거쳐야 합니다.

2-2. 주요 프로토콜

프로토콜설명주요 특징
OpenVPNTLS 기반 오픈소스 VPN유연하지만 느림, 복잡한 설정
IPsec/IKEv2네트워크 계층 암호화표준 호환, 기업 선호, 설정 복잡
L2TP/IPsec레거시 터널링레거시 지원, 보안 취약점 있음
WireGuard현대적 경량 VPN빠름, 단순, Tailscale이 사용
PPTP구형 프로토콜보안 취약, 사용 권장 안 함

2-3. 전통 VPN의 한계

  • 단일 장애점(Single Point of Failure): 게이트웨이가 다운되면 전체 VPN 불통
  • 병목 현상(Bottleneck): 모든 트래픽이 중앙 서버 경유 → 지연 증가
  • 복잡한 설정: 인증서, NAT 룰, 방화벽 설정 등 관리 부담
  • 확장성 한계: 노드 수 증가 시 서버 부하 급증
  • NAT 통과 문제: 방화벽/NAT 뒤의 피어 간 직접 통신 어려움

3. Tailscale 개요 (Tailscale Overview)

Tailscale이란?

Tailscale은 WireGuard 프로토콜을 기반으로 구축된 메시 VPN(Mesh VPN) 서비스입니다. 2019년 설립되었으며, "Zero config VPN"을 표방합니다. 복잡한 서버 설정 없이 각 디바이스가 직접 P2P(Peer-to-Peer) 암호화 연결을 맺는 것이 핵심입니다.

핵심 철학

  • Zero Trust Network: 네트워크 위치가 아닌 신원(identity) 기반 접근 제어
  • 사용 편의성: 10분 내 설정 완료 목표
  • 분산 아키텍처: 중앙 데이터 경로 없이 P2P 직접 연결
  • 기존 IdP 활용: Google, GitHub, Microsoft 등 SSO 연동
Tailnet: Tailscale에서 같은 조직의 디바이스들이 형성하는 네트워크를 tailnet이라고 부릅니다. tailnet 내 모든 노드는 고유한 IP(100.x.x.x 범위)를 가집니다.

4. Tailscale의 핵심 기술 (Core Technology: WireGuard + Mesh)

4-1. WireGuard 기반

WireGuard는 Linux 커널에 통합된 현대적 VPN 프로토콜입니다. OpenVPN 대비 코드 라인 수가 1/100 수준(~4,000줄)이며, 성능과 보안이 뛰어납니다.

항목WireGuardOpenVPN
코드 크기~4,000줄~70,000줄
암호화ChaCha20, Poly1305, Curve25519OpenSSL (다양)
핸드셰이크 속도매우 빠름 (1-RTT)느림 (TLS 다단계)
커널 통합Linux 5.6+ 내장유저스페이스
보안 감사단순 → 검증 용이복잡 → 취약점 발견 어려움

4-2. Mesh 네트워크 토폴로지

전통 VPN이 Hub-and-Spoke인 반면, Tailscale은 풀 메시(Full Mesh) 또는 부분 메시(Partial Mesh) 토폴로지를 사용합니다. 각 노드가 다른 모든 노드와 직접 연결됩니다.

Hub-and-Spoke (전통 VPN) Mesh (Tailscale) A ──→ [서버] ←── B A ─────── B C ──→ [서버] ←── D │ ╲ ╱ │ │ ╲ ╱ │ A↔B 통신: A→서버→B │ ╱ ╲ │ │ ╱ ╲ │ C ─────── D A↔B 통신: A→B (직접)

4-3. Control Plane vs Data Plane 분리

Control Plane (제어 평면) — Tailscale 서버

키 배포, 노드 등록, ACL 정책 배포를 담당합니다. Tailscale의 중앙 서버(controlplane.tailscale.com)는 어떤 실제 데이터 패킷도 처리하지 않습니다. 오직 노드 공개 키와 주소를 교환하는 역할만 합니다.

Data Plane (데이터 평면) — P2P 직접 연결

실제 트래픽은 노드 간 WireGuard 터널로 직접 전달됩니다. Tailscale 서버는 데이터 경로에 없으므로, 서버가 다운되어도 이미 수립된 연결은 유지됩니다. 

# WireGuard 키 교환 과정 (Tailscale이 관리하는 부분)
# 각 노드는 공개키/개인키 쌍을 생성
$ wg genkey | tee privatekey | wg pubkey > publickey

# Tailscale Control Server가 중개:
# Node A 공개키 → Control Server → Node B
# Node B 공개키 → Control Server → Node A
# 이후 A↔B는 WireGuard로 직접 암호화 통신

5. DERP 릴레이와 NAT 통과 (DERP Relay & NAT Traversal)

5-1. NAT 통과 (NAT Traversal)

현실 세계에서 대부분의 디바이스는 NAT(Network Address Translation) 뒤에 있어 직접 P2P 연결이 어렵습니다. Tailscale은 다양한 NAT 통과 기법을 자동으로 시도합니다.

  • STUN (Session Traversal Utilities for NAT): 외부 IP/포트 탐색
  • ICE (Interactive Connectivity Establishment): 최적 경로 협상
  • UDP 홀 펀칭 (UDP Hole Punching): NAT를 통한 직접 연결 수립
[노드 A] [노드 B] NAT 뒤 (192.168.1.5) NAT 뒤 (10.0.0.8) │ │ ├── STUN 요청 → [Tailscale 조정 서버] ←─┤ │ (외부 IP:포트 교환) │ │ │ └──────── UDP 홀 펀칭 직접 연결 ────────┘ 성공 시: 직접 P2P 통신

5-2. DERP (Designated Encrypted Relay for Packets)

P2P 직접 연결이 불가능한 경우(엄격한 방화벽, 대칭 NAT 등)를 위해 Tailscale은 DERP 릴레이 서버를 제공합니다.

DERP는 최후의 수단(fallback)입니다. Tailscale은 항상 먼저 직접 P2P 연결을 시도하고, 불가능할 때만 DERP를 사용합니다. DERP 서버도 패킷 내용을 볼 수 없습니다 — 엔드-투-엔드 암호화된 패킷을 불투명하게 전달합니다.
직접 연결 불가 시: [노드 A] ──암호화 패킷──→ [DERP 서버] ──암호화 패킷──→ [노드 B] (DERP 서버는 내용 해독 불가 — 주소 정보만 사용)

전 세계 여러 지역에 DERP 서버가 분산 배치되어 있어(도쿄, 서울, 싱가포르 등) 릴레이가 필요해도 지연이 최소화됩니다.

7. 다른 Modern VPN 솔루션과 비교 (Comparison with Other Modern VPN Solutions)

Headscale 오픈소스 Tailscale Control Server

Tailscale의 Control Plane을 직접 자체 호스팅하고 싶을 때 사용하는 오픈소스 구현체입니다. 데이터 주권(data sovereignty)이 중요한 기업에서 선호합니다. 클라이언트는 동일한 Tailscale 앱을 사용합니다.

  • 장점: 완전한 자체 호스팅, 비용 없음
  • 단점: 운영 부담, 일부 Tailscale 기능 미지원 (MagicDNS 등)

ZeroTier SDN 기반 Mesh VPN

ZeroTier는 L2 이더넷 레벨의 가상 네트워크를 제공합니다. WireGuard가 아닌 자체 프로토콜을 사용하며, 가상 스위치처럼 동작합니다.

항목TailscaleZeroTier
레이어L3 (IP)L2 (이더넷)
프로토콜WireGuard자체 ZeroTier 프로토콜
성능빠름보통
자체 호스팅Headscale 필요ZeroTier Central 자체 가능
설정 편의성더 쉬움다소 복잡

Nebula Slack이 오픈소스로 공개한 Mesh VPN

Slack이 내부적으로 사용하다 공개한 Mesh VPN 도구입니다. 완전한 자체 호스팅이 가능하며, "Lighthouse"라는 코디네이터 노드를 사용합니다. Tailscale보다 설정이 복잡하지만 Control Plane 서버가 필요 없습니다.

Netbird 오픈소스 WireGuard Mesh

Tailscale과 매우 유사한 오픈소스 대안입니다. 완전 자체 호스팅 가능하며, Keycloak 등 자체 IdP 연동을 지원합니다.

8. 보안 모델 (Security Model)

8-1. Zero Trust 아키텍처

전통 VPN은 "내부 네트워크는 신뢰, 외부는 불신"이라는 경계 기반 보안(Perimeter Security) 모델을 사용합니다. Tailscale은 Zero Trust를 채택합니다: 네트워크에 연결되어 있다는 사실만으로는 신뢰를 부여하지 않으며, 모든 접근은 신원 기반으로 검증됩니다.

8-2. ACL (Access Control List)

Tailscale ACL은 JSON 형식으로 사용자, 그룹, 태그, 포트 수준에서 세밀한 접근 제어를 정의합니다. 

{
  "acls": [
    // 개발팀은 개발 서버에만 SSH 가능
    {
      "action": "accept",
      "src": ["group:dev"],
      "dst": ["tag:dev-server:22"]
    },
    // 운영팀은 모든 서버에 접근 가능
    {
      "action": "accept",
      "src": ["group:ops"],
      "dst": ["tag:server:*"]
    }
  ]
}

8-3. 신뢰 경계

주의: Tailscale의 Control Plane은 Tailscale Inc.가 운영합니다. 키 교환 메타데이터는 Tailscale 서버를 통하므로, 완전한 자체 주권이 필요하다면 Headscale 자체 호스팅을 고려해야 합니다. 단, 실제 트래픽 데이터는 Tailscale 서버를 통과하지 않습니다.

8-4. MagicDNS와 HTTPS 인증서

Tailscale은 MagicDNS 기능으로 각 노드에 nodename.tailnet.ts.net 형태의 DNS 이름을 자동 부여하고, Let's Encrypt를 통한 HTTPS 인증서 자동 발급도 지원합니다.

9. 실제 사용 사례 (Real-World Use Cases)

사례 1: 원격 근무 환경 (Remote Work)

재택 근무자가 회사 내부 개발 서버에 접근할 때, 전통 VPN 서버 없이 Tailscale 앱 설치만으로 직접 연결. 지연 감소, 설정 간소화.

사례 2: 홈랩 / 자택 서버 접근 (Homelab)

집의 NAS나 Raspberry Pi에 외부에서 접근할 때. 포트포워딩, 공인 IP 불필요. Tailscale 설치만으로 어느 곳에서든 접근 가능.

사례 3: 멀티 클라우드 연결 (Multi-Cloud)

AWS, GCP, Azure의 서버들을 하나의 사설 네트워크처럼 연결. 각 클라우드의 VPC Peering 복잡성 없이 Tailscale로 통합 관리.

사례 4: CI/CD 파이프라인 보안

GitHub Actions나 GitLab CI에서 내부 서버에 안전하게 접근할 때 Tailscale GitHub Action을 사용. 임시 ephemeral 노드로 잠깐 연결 후 자동 삭제. 

- name: Setup Tailscale
  uses: tailscale/github-action@v2
  with:
    authkey: ${{ secrets.TAILSCALE_AUTHKEY }}
    args: --ephemeral

사례 5: Subnet Router (서브넷 라우터)

Tailscale을 설치할 수 없는 레거시 장비(프린터, IoT 기기 등)가 있는 네트워크에서, 한 노드를 Subnet Router로 지정하여 해당 서브넷 전체를 tailnet에 노출 가능.

10. 장단점 요약 (Pros & Cons Summary)

장점 (Advantages)
  • 설정이 매우 간단 (5분 내 구축)
  • P2P 직접 연결로 낮은 지연
  • 자동 NAT 통과
  • WireGuard의 현대적 보안
  • Zero Trust 기반 세밀한 ACL
  • SSO 연동 (MFA 지원)
  • 단일 장애점 없음
  • 무료 플랜 충분히 실용적
  • 크로스 플랫폼 (macOS/Win/Linux/iOS/Android)
단점 (Disadvantages)
  • Control Plane이 외부 SaaS (Tailscale Inc. 의존)
  • 완전 자체 호스팅은 Headscale 필요 (공식 지원 아님)
  • 대규모 엔터프라이즈 기능은 유료
  • 인터넷 연결 필수 (Control Plane 접근)
  • 일부 엄격한 방화벽 환경에서 DERP 의존 가능성
  • 전통적 네트워크 구조 대비 디버깅 어려울 수 있음
