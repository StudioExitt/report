1 개요 — GitHub Pages란? (What is GitHub Pages?)

GitHub Pages는 GitHub 저장소에서 직접 정적 웹사이트를 호스팅할 수 있는 서비스입니다. 별도의 서버 비용 없이, 마크다운(Markdown)이나 HTML 파일만으로 문서 사이트·프로젝트 소개 페이지를 만들 수 있습니다.

💡 핵심 개념: GitHub Pages는 정적 파일(static files)만 호스팅합니다. 서버사이드 코드(PHP, Node.js 등)는 실행되지 않으며, 데이터베이스도 사용할 수 없습니다.

GitHub Pages를 사용할 수 있는 방법은 크게 두 가지입니다:

  • ① Repository Docs 페이지 — 프로젝트 저장소 안에 docs 폴더나 특정 브랜치를 지정해 문서를 게시
  • ② GitHub.io 페이지 — username.github.io 형식의 전용 저장소를 만들어 사용자/조직 사이트를 운영

2 Repository 내 Docs 페이지 구성하기 (Setting Up Docs Pages in a Repository)

2-1. 소스(Source) 옵션 선택

프로젝트 저장소에서 GitHub Pages를 활성화하려면 Settings → Pages로 이동합니다. "Build and deployment" 섹션에서 소스를 선택할 수 있습니다.

소스 옵션 설명 추천 상황
main 브랜치 / root 저장소 루트의 모든 파일을 웹사이트로 제공 문서만 있는 저장소
main 브랜치 / /docs 저장소 루트의 docs/ 폴더 내용만 게시 코드와 문서를 한 저장소에 같이 둘 때 가장 일반적
gh-pages 브랜치 별도의 브랜치를 생성해 빌드 결과물만 게시 CI/CD 자동화로 빌드 후 배포할 때
GitHub Actions 워크플로우가 직접 Pages에 배포 복잡한 빌드 파이프라인 (Next.js, Astro 등)

2-2. /docs 폴더 방식 (Step-by-step)

1
저장소에 docs/ 폴더 생성

저장소 루트에 docs/index.html 또는 docs/index.md 파일을 만듭니다.

2
Settings → Pages 설정

Branch를 main, 폴더를 /docs로 선택 후 저장합니다.

3
자동 배포 확인

몇 분 내로 https://username.github.io/repository-name/ 주소로 접근 가능합니다.

2-3. 생성되는 URL 구조

# 프로젝트 저장소 docs 페이지 URL 패턴
https://username.github.io/repository-name/

# 예시: octocat 사용자의 my-project 저장소
https://octocat.github.io/my-project/

2-4. Jekyll 자동 처리

GitHub Pages는 기본적으로 Jekyll (static site generator)을 사용하여 마크다운 파일을 자동으로 HTML로 변환합니다. _config.yml 파일로 테마와 설정을 커스터마이즈할 수 있습니다.

# docs/_config.yml 예시
title: "My Project Documentation"
description: "프로젝트 공식 문서"
theme: minima
remote_theme: just-the-docs/just-the-docs  # 문서에 최적화된 테마

nav_enabled: true
search_enabled: true

3 GitHub.io 페이지 구성하기 (Setting Up GitHub.io — User/Organization Pages)

GitHub.io 페이지는 특별한 이름 규칙(username.github.io)을 가진 저장소를 만들어 운영하는 사용자 또는 조직 전용 사이트입니다.

1
저장소 이름을 정확히 username.github.io로 생성

예: GitHub 아이디가 octocat이라면 저장소명은 octocat.github.io

2
루트에 index.html 또는 index.md 생성

별도의 Pages 설정 없이 main 브랜치 푸시만으로 자동 게시됩니다.

3
접근 URL 확인

https://username.github.io — 경로 없이 루트로 접근 가능

# GitHub.io 저장소 URL 패턴
https://username.github.io/

# 예시
https://octocat.github.io/

# 조직(Organization) 페이지
https://org-name.github.io/
✅ 포트폴리오·개인 블로그에 이상적: 루트 도메인을 사용하므로 깔끔한 URL을 제공합니다. 커스텀 도메인 연결 시 가장 간단한 설정으로 운영할 수 있습니다.

4 핵심 차이점 비교 (Key Differences)

📁 Repository Docs 페이지
  • 일반 저장소 안에 /docs 폴더 또는 gh-pages 브랜치 사용
  • URL에 저장소 이름이 포함됨: .../repo-name/
  • 코드 + 문서를 하나의 저장소에서 관리
  • 프로젝트별 독립된 문서 관리에 적합
  • Pages 소스를 수동으로 설정해야 함
🌐 GitHub.io (사용자/조직 페이지)
  • 저장소명 = username.github.io (고정 규칙)
  • 루트 URL 사용: https://username.github.io
  • 개인 포트폴리오·블로그·조직 메인 사이트에 적합
  • 계정당 1개만 생성 가능
  • 별도 Pages 설정 없이 자동 활성화
항목 Repository Docs 페이지 GitHub.io 페이지
저장소 이름 자유롭게 지정 가능 반드시 username.github.io
URL 형식 username.github.io/repo-name/ username.github.io/
URL 경로 깊이 서브패스 포함 (하위 경로 존재) 루트 경로 (최상위)
개수 제한 계정당 무제한 (저장소 수만큼) 계정당 1개만
Pages 활성화 Settings에서 수동 설정 필요 저장소 생성만으로 자동 활성화
소스 위치 /docs 폴더, gh-pages 브랜치, Actions 등 선택 main 브랜치 루트 (기본)
주요 용도 프로젝트 API 문서, 라이브러리 가이드 개인 포트폴리오, 블로그, 조직 메인
Jekyll 처리 기본 지원 (비활성화 가능) 기본 지원 (비활성화 가능)
커스텀 도메인 지원 (CNAME 파일 사용) 지원 (가장 일반적인 설정)
공개/비공개 무료 플랜 = 공개 저장소만 무료 동일
⚠️ 경로(Path) 문제 주의: Repository Docs 페이지는 URL에 /repo-name/이 포함됩니다. HTML의 절대경로(/style.css)를 사용하면 깨집니다. Jekyll의 {{ site.baseurl }} 또는 상대경로(./style.css)를 사용하세요.

5 어떤 방식을 선택해야 할까? (Which One Should You Choose?)

Repository Docs 페이지를 선택하세요 — 이런 경우

  • 오픈소스 라이브러리나 프레임워크의 공식 문서를 만들 때
  • 코드와 문서를 같은 저장소에서 버전 관리할 때
  • 여러 프로젝트가 각각 독립된 문서 사이트가 필요할 때
  • API 레퍼런스, 튜토리얼을 프로젝트 단위로 관리할 때

GitHub.io 페이지를 선택하세요 — 이런 경우

  • 개인 포트폴리오나 이력서 사이트를 만들 때
  • 기술 블로그를 운영할 때 (Jekyll, Hugo 활용)
  • 조직의 메인 랜딩 페이지가 필요할 때
  • 깔끔한 루트 URL(username.github.io)이 필요할 때
💡 병행 사용 가능: username.github.io (개인 사이트) + username.github.io/project-docs/ (프로젝트 문서)를 함께 운영할 수 있습니다. 서로 독립적으로 관리되며 충돌하지 않습니다.

6 커스텀 도메인 설정 (Custom Domain Setup)

6-1. CNAME 파일 추가

저장소 루트(또는 docs/ 폴더)에 CNAME 파일을 생성하고 도메인을 입력합니다.

# CNAME 파일 내용 (확장자 없음)
www.mydomain.com

6-2. DNS 설정

도메인 유형 DNS 레코드 타입 값
Apex 도메인 (mydomain.com) A 레코드 185.199.108.153 (외 3개 GitHub IP)
서브도메인 (www.mydomain.com) CNAME 레코드 username.github.io
🔒 커스텀 도메인 설정 후 Settings → Pages에서 Enforce HTTPS를 활성화하면 Let's Encrypt 인증서가 자동으로 발급됩니다.

7 Jekyll & GitHub Actions 자동화 (Jekyll & GitHub Actions Automation)

7-1. GitHub Actions로 Docs 빌드 자동화

더 복잡한 문서 사이트(Docusaurus, MkDocs, VitePress 등)는 GitHub Actions로 빌드 후 배포합니다.

# .github/workflows/deploy-docs.yml
name: Deploy Docs
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci && npm run docs:build
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs/.vitepress/dist

7-2. Jekyll 비활성화 (.nojekyll)

Next.js, Vue Press 등 자체 빌드 도구를 사용할 때는 Jekyll 처리를 꺼야 합니다.

# 루트 또는 docs/ 폴더에 빈 파일 생성
touch .nojekyll

8 실전 팁 & 주의사항 (Practical Tips & Caveats)

✅ 알아두면 좋은 것들

  • 빌드 시간 제한 (Build time limit): GitHub Pages 빌드는 10분 제한이 있습니다. 대용량 사이트는 Actions로 빌드하고 결과물만 배포하세요.
  • 용량 제한 (Storage limit): 저장소 크기 1GB, 배포된 사이트 크기 1GB, 월 대역폭 100GB 소프트 제한이 있습니다.
  • Private 저장소 (Private repositories): 무료 플랜(Free plan)에서는 공개 저장소만 Pages를 무료로 사용할 수 있습니다. 비공개 저장소는 GitHub Pro/Team/Enterprise 플랜이 필요합니다.
  • 캐싱 (Caching): 배포 후 변경사항이 바로 반영되지 않을 수 있습니다. 브라우저 캐시를 지우거나 강력 새로고침(Ctrl+Shift+R)을 시도하세요.
  • 서버사이드 불가 (No server-side processing): PHP, Python 서버, DB 연결 등은 사용 불가합니다. 폼 처리는 Formspree 같은 외부 서비스를 사용하세요.

⚠️ 흔한 실수들

  • Repository Docs 페이지에서 절대경로(/assets/img.png) 사용 — baseurl을 설정하지 않으면 이미지/CSS가 깨짐
  • username.github.io 저장소를 Private으로 만들면 Pages가 비활성화됨
  • Jekyll이 처리하지 않길 원하는데 .nojekyll 파일을 빠뜨리는 경우
  • gh-pages 브랜치 보호 규칙(branch protection)을 설정하면 자동 배포가 막힐 수 있음
