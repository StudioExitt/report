Windows Git Bash에서 rsync를 이용해 Linux로 파일 동기화

Syncing files from Windows Git Bash to a Linux server using rsync — 설치, SSH 연동, 경로 함정, 실전 명령어까지

1. 개요 Overview

이 문서는 Windows 환경에서 Git Bash를 이용해 rsync로 원격 Linux 서버와 파일을 동기화하는 방법을 정리한 스터디 노트입니다. 대상 독자는 Windows 개발 환경에서 작업하면서 배포 서버나 원격 Linux 개발 서버로 파일을 빠르고 안전하게 동기화해야 하는 개발자입니다. Git Bash는 MSYS2 기반 Unix 유사 셸을 제공하지만 rsync를 기본 포함하지 않기 때문에, 설치 방법과 Windows 특유의 경로 변환 문제를 함께 다룹니다.

2. 핵심 개념 정의 Key Concepts

용어 정의
rsync
Remote Sync		 두 위치(로컬↔로컬, 로컬↔원격) 간 파일을 델타(차이분)만 전송하는 방식으로 동기화하는 유틸리티. 전체 파일을 매번 복사하지 않아 반복 동기화 시 빠름
Git Bash Windows용 Git 배포판에 포함된 터미널 에뮬레이터. 내부적으로 MSYS2 런타임(POSIX 호환 레이어)을 사용해 bash, ssh 등 Unix 명령을 Windows에서 실행 가능하게 함
MSYS2 Windows에서 POSIX 호환 개발 환경과 pacman 기반 패키지 저장소를 제공하는 프로젝트. Git Bash가 이 런타임 위에서 동작
경로 변환 Path Translation MSYS2 계열은 C:\Users\me를 /c/Users/me로 표기하고, Cygwin 계열은 /cygdrive/c/Users/me로 표기함. 두 표기법이 섞이면 rsync가 경로를 찾지 못하는 오류 발생

3. 사전 준비 Prerequisites

  • Windows에 Git for Windows 설치 (Git Bash 포함)
  • 동기화 대상 Linux 서버에 SSH 접속 가능 (계정, 포트, 필요 시 SSH 키)
  • Linux 서버에는 대부분 배포판에 rsync가 기본 포함되어 있으나, 없다면 sudo apt install rsync 등으로 설치
중요 Important

Git for Windows에는 rsync 바이너리가 기본 포함되어 있지 않습니다. rsync: command not found 오류가 뜨면 아래 4장의 설치 절차가 필요합니다.

4. Git Bash에 rsync 설치 Installing rsync in Git Bash

Git Bash는 MSYS2 런타임을 쓰지만 rsync 패키지 자체는 빠져 있습니다. 가장 널리 쓰이는 방법은 MSYS2 공식 저장소에서 rsync 패키지를 받아 Git Bash의 bin 폴더에 직접 넣는 것입니다.

방법 A. MSYS2 패키지 수동 설치 (권장) Manual MSYS2 Package (Recommended)

  1. MSYS2 패키지 저장소에서 rsync-*.pkg.tar.zst 최신 버전을 다운로드
  2. 7-Zip 등으로 압축을 풀어 usr/bin/rsync.exe를 추출
  3. rsync.exe를 Git 설치 경로의 C:\Program Files\Git\usr\bin에 복사
  4. DLL 의존성 오류(libzstd-1.dll, liblz4-1.dll, libxxhash-0.dll 등)가 나면 동일한 MSYS2 저장소에서 해당 패키지를 받아 같은 폴더에 함께 복사
# Git Bash에서 설치 확인
rsync --version

버전 정보가 정상 출력되면 설치가 완료된 것입니다.

출처: Prasanna Wijesiriwardana – Add rsync to Windows Git Bash, radleta – Step-by-step rsync with Git Bash

방법 B. cwRsync 클라이언트 사용 Using cwRsync Client

Cygwin 기반으로 빌드된 cwRsync 배포판을 받아 압축 해제 후 bin 폴더를 시스템 PATH에 추가하는 방법도 있습니다. 다만 Cygwin 경로 표기(/cygdrive/c/...)를 사용하므로 Git Bash(MSYS2)의 /c/... 표기와 섞이면 6장에서 다루는 경로 문제가 발생하기 쉽습니다.

출처: tlundberg.com – Installing rsync on Windows

5. SSH 연동 설정 SSH Setup

rsync는 원격 전송 시 내부적으로 ssh를 전송 채널로 사용합니다. Git Bash에는 ssh 클라이언트가 기본 포함되어 있으므로 별도 설치는 불필요합니다.

# 1) SSH 키 생성 (이미 있다면 생략)
ssh-keygen -t ed25519 -C "sb.park@toss.im"

# 2) 공개키를 Linux 서버에 등록
ssh-copy-id user@linux-server

# 3) 접속 테스트
ssh user@linux-server

ssh-copy-id가 Windows Git Bash에서 동작하지 않는 환경이라면, cat ~/.ssh/id_ed25519.pub로 공개키를 출력해 수동으로 서버의 ~/.ssh/authorized_keys에 추가합니다.

6. Windows 경로 함정 Windows Path Pitfalls

Windows 로컬 경로를 rsync에 넘길 때 표기법이 맞지 않으면 No such file or directory 오류가 발생합니다.

표기법 예시 (C:\Users\me\project) 사용 환경
MSYS2 스타일 /c/Users/me/project Git Bash (기본)
Cygwin 스타일 /cygdrive/c/Users/me/project cwRsync, Cygwin rsync
Windows 원본 경로 C:\Users\me\project rsync에 직접 사용 불가 (콜론 :이 원격 호스트 구분자와 충돌)
흔한 오류 Common Pitfall

Windows 경로의 드라이브 콜론(C:)은 rsync의 host:path 구분자와 충돌해 잘못 해석될 수 있습니다. 반드시 /c/... 형태로 변환해서 사용하고, Git Bash와 cwRsync를 함께 설치했다면 PATH에서 어느 rsync.exe가 먼저 잡히는지 확인해야 합니다.

출처: GitHub Issue – hashicorp/vagrant #4073 (Rsync on Windows fails – lacks /cygdrive prefix)

7. 기본 사용법 Basic Usage

로컬 Windows 프로젝트 폴더를 원격 Linux 서버로 동기화하는 가장 기본적인 명령입니다.

# 로컬 → 원격 동기화 (업로드)
rsync -avz -e ssh /c/Users/me/project/ user@linux-server:/home/user/project/

# 원격 → 로컬 동기화 (다운로드)
rsync -avz -e ssh user@linux-server:/home/user/project/ /c/Users/me/project/
슬래시(/) 주의 Trailing Slash Matters

소스 경로 끝에 /가 있으면 "폴더 안의 내용물"을 동기화하고, 없으면 "폴더 자체"를 대상 경로 밑에 복사합니다. 예상과 다른 위치에 파일이 생기는 실수의 대부분은 이 슬래시 유무 때문입니다.

8. 자주 쓰는 옵션 Common Flags

옵션 설명
-a
archive		 권한·심볼릭 링크·타임스탬프 등을 보존하며 하위 디렉터리까지 재귀적으로 동기화 (-rlptgoD의 축약)
-v
verbose		 전송 중인 파일 목록을 출력
-z
compress		 전송 시 데이터를 압축 — 네트워크가 느릴 때 유용
-e ssh 전송 프로토콜로 SSH를 사용하도록 지정 (포트 변경 시 -e "ssh -p 2222")
--delete 소스에는 없는데 대상에만 있는 파일을 삭제하여 완전히 미러링. 삭제를 동반하므로 신중히 사용

--exclude 특정 패턴의 파일/폴더를 동기화 대상에서 제외 (예: --exclude 'node_modules/')
--progress 파일별 전송 진행률 표시

9. 실전 예시 Practical Example

Windows에서 작업 중인 프로젝트를 .git, node_modules 등 불필요한 폴더는 제외하고, 먼저 dry-run으로 확인한 뒤 실제 동기화하는 흐름입니다.

# 1) 사전 확인 (실제 전송 없이 변경 사항만 확인)
rsync -avzn --delete \
  --exclude '.git/' \
  --exclude 'node_modules/' \
  -e "ssh -p 22" \
  /c/Users/me/project/ user@linux-server:/home/user/project/

# 2) 실제 동기화 실행
rsync -avz --delete \
  --exclude '.git/' \
  --exclude 'node_modules/' \
  -e "ssh -p 22" \
  /c/Users/me/project/ user@linux-server:/home/user/project/
팁 Tip

매번 긴 명령을 입력하기 번거롭다면 ~/.bashrc에 셸 함수나 별칭으로 등록해두면 편리합니다.

# ~/.bashrc
sync-to-server() {
  rsync -avz --delete \
    --exclude '.git/' \
    --exclude 'node_modules/' \
    -e ssh \
    /c/Users/me/project/ user@linux-server:/home/user/project/
}

10. 트러블슈팅 Troubleshooting

증상 원인 및 해결
rsync: command not found 4장의 방법으로 rsync 바이너리를 Git Bash usr/bin에 설치하지 않은 경우
rsync 실행 시 DLL 오류로 즉시 종료 rsync.exe가 동적으로 링크하는 libzstd-1.dll 등 의존 DLL이 없는 경우. MSYS2 저장소에서 해당 DLL 패키지를 받아 같은 폴더에 배치
No such file or directory (경로가 분명 존재하는데도) 6장의 경로 표기법 불일치. C:\... 대신 /c/... 형식 사용, 설치된 rsync가 MSYS2/Cygwin 중 어느 것인지 확인
모든 파일의 권한/타임스탬프가 매번 변경된 것으로 감지됨 NTFS는 POSIX 파일 권한을 그대로 지원하지 않아 -a의 권한 보존이 왜곡될 수 있음. 로컬↔윈도우 동기화에서는 --no-perms --no-owner --no-group 옵션 추가를 고려
텍스트 파일 내용이 서버에서 깨져 보임 Git의 core.autocrlf 설정으로 인한 개행 문자(CRLF↔LF) 변환 문제일 수 있음 — rsync 자체는 바이너리 그대로 전송하므로, 원본 파일이 이미 CRLF로 저장된 경우가 원인

11. 요약 Summary

  • Git Bash에는 rsync가 기본 포함되어 있지 않으므로 MSYS2 패키지에서 rsync.exe를 별도로 가져와야 함
  • 원격 동기화는 SSH를 전송 채널로 사용하며, Git Bash에 내장된 ssh로 키 기반 인증을 먼저 구성하는 것이 효율적
  • Windows 경로는 반드시 /c/... 형식(MSYS2 스타일)으로 변환하며, Cygwin 계열 도구와 혼용하지 않도록 주의
  • 소스 경로의 트레일링 슬래시 유무가 동기화 결과 구조를 결정하므로 항상 --dry-run으로 먼저 확인하는 습관이 안전함
