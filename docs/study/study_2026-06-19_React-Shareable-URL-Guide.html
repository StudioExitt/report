1. 개요 (Overview)

React는 기본적으로 SPA(Single Page Application)로 동작합니다. SPA에서는 JavaScript가 DOM을 직접 교체하기 때문에, 사용자가 페이지를 이동해도 브라우저의 URL이 바뀌지 않습니다. 이를 해결하지 않으면 공유, 북마크, 뒤로가기가 모두 깨집니다.

(React is a SPA by default — without proper routing, all users land on the same URL regardless of what they're viewing.)

왜 URL이 중요한가? (Why URL Matters)

문제 상황

  • 모든 페이지가 / 하나로만 접근됨
  • 링크 공유 시 항상 홈으로 이동
  • 뒤로가기/앞으로가기 동작 안 함
  • 검색엔진 크롤링 불가 (SEO 손해)
  • 사용자가 특정 상태로 돌아올 수 없음

해결 후 이점

  • 각 화면마다 고유 URL 보유
  • 북마크 · 링크 공유 완벽 동작
  • 브라우저 히스토리 정상 동작
  • 필터/검색 조건도 URL에 유지
  • SEO 및 접근성 향상
핵심 개념 (Key Concept): React에서 URL을 관리하는 것 = 브라우저 History API를 React 컴포넌트 트리와 연결하는 것입니다.

2. React Router 기초 (React Router Basics)

React Router는 React에서 URL 라우팅을 담당하는 사실상의 표준 라이브러리입니다. 2024년 기준 v6이 최신이며, Remix(현 React Router v7)도 같은 생태계입니다.

설치 (Installation)

# npm
npm install react-router-dom

# yarn
yarn add react-router-dom

# pnpm
pnpm add react-router-dom

BrowserRouter vs HashRouter

종류 URL 형태 서버 설정 필요 추천 상황
BrowserRouter /users/123 필요 (fallback 설정) 일반적인 웹앱 (권장)
HashRouter /#/users/123 불필요 정적 파일 호스팅 (GitHub Pages 등)
MemoryRouter URL 변경 없음 불필요 테스트, React Native
BrowserRouter 사용 시 주의: Nginx/Apache 등에서 try_files $uri /index.html 설정이 필요합니다. 없으면 새로고침 시 404 오류가 발생합니다.

기본 라우팅 구성 (Basic Routing Setup)

// src/main.tsx (또는 index.tsx)
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { BrowserRouter } from 'react-router-dom'
import App from './App'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>
)
// src/App.tsx
import { Routes, Route, Link } from 'react-router-dom'
import HomePage from './pages/HomePage'
import UserPage from './pages/UserPage'
import NotFoundPage from './pages/NotFoundPage'

function App() {
  return (
    <>
      <nav>
        {/* Link는 <a> 태그를 사용하지만 페이지 새로고침 없이 이동 */}
        <Link to="/">홈</Link>
        <Link to="/users">사용자 목록</Link>
      </nav>

      <Routes>
        <Route path="/"        element={<HomePage />} />
        <Route path="/users"   element={<UserListPage />} />
        <Route path="/users/:id" element={<UserPage />} />
        <Route path="*"        element={<NotFoundPage />} />
      </Routes>
    </>
  )
}

export default App

3. URL 파라미터 (URL Parameters / Dynamic Segments)

URL 파라미터는 경로에 :변수명 형태로 포함되는 동적 값입니다. 리소스를 식별하는 데 사용됩니다.

(URL parameters are dynamic segments in the path that identify a specific resource.)

예시: /users/42, /posts/hello-world, /products/iphone-15-pro

useParams 훅 사용 (Using useParams Hook)

// src/pages/UserPage.tsx
import { useParams } from 'react-router-dom'

function UserPage() {
  // Route path="/users/:userId" 로 정의했을 때
  const { userId } = useParams<{ userId: string }>()

  return <div>사용자 ID: {userId}</div>
}

// 중첩 파라미터 예시: /teams/:teamId/members/:memberId
function MemberPage() {
  const { teamId, memberId } = useParams()
  return <div>팀 {teamId}의 멤버 {memberId}</div>
}

프로그래매틱 네비게이션 (Programmatic Navigation)

import { useNavigate } from 'react-router-dom'

function UserCard({ user }) {
  const navigate = useNavigate()

  const handleClick = () => {
    // 문자열로 이동
    navigate(`/users/${user.id}`)

    // 객체 형태 (replace: true → 히스토리 교체)
    navigate({ pathname: `/users/${user.id}` }, { replace: true })

    // 뒤로가기
    navigate(-1)
  }

  return <button onClick={handleClick}>{user.name} 보기</button>
}
베스트 프랙티스: URL 파라미터에는 리소스 식별자만 넣으세요. 예) ID, slug. 표시 옵션(정렬, 필터 등)은 쿼리스트링을 사용합니다.

4. 쿼리스트링 (Query String / Search Params)

쿼리스트링은 URL에서 ? 뒤에 오는 key=value 형태의 파라미터입니다. 검색, 필터, 정렬, 페이지네이션 등 UI 상태를 URL에 담을 때 사용합니다.

예시: /products?category=shoes&sort=price&page=2

useSearchParams 훅 사용 (React Router v6)

import { useSearchParams } from 'react-router-dom'

function ProductListPage() {
  // useState와 유사한 인터페이스!
  const [searchParams, setSearchParams] = useSearchParams()

  // 읽기
  const category = searchParams.get('category') ?? 'all'
  const sort     = searchParams.get('sort')     ?? 'newest'
  const page     = Number(searchParams.get('page')  ?? '1')

  // 쓰기 (기존 파라미터 유지하면서 일부만 변경)
  const handleCategoryChange = (newCategory: string) => {
    setSearchParams(prev => {
      prev.set('category', newCategory)
      prev.set('page', '1') // 필터 변경 시 첫 페이지로
      return prev
    })
  }

  return (
    <div>
      <select value={category} onChange={e => handleCategoryChange(e.target.value)}>
        <option value="all">전체</option>
        <option value="shoes">신발</option>
      </select>
      {/* 현재 URL: /products?category=shoes&page=1 */}
    </div>
  )
}

커스텀 훅으로 추상화 (Custom Hook Pattern)

// hooks/useQueryParam.ts
import { useSearchParams } from 'react-router-dom'

/**
 * 단일 쿼리 파라미터를 useState처럼 사용하는 훅
 * A hook that manages a single query param like useState
 */
export function useQueryParam(key: string, defaultValue = '') {
  const [searchParams, setSearchParams] = useSearchParams()
  const value = searchParams.get(key) ?? defaultValue

  const setValue = (newValue: string) => {
    setSearchParams(prev => {
      if (newValue === defaultValue) {
        prev.delete(key) // 기본값이면 URL에서 제거 (깔끔한 URL)
      } else {
        prev.set(key, newValue)
      }
      return prev
    }, { replace: true }) // 히스토리 쌓지 않음
  }

  return [value, setValue] as const
}

// 사용 예시
function SearchPage() {
  const [query, setQuery] = useQueryParam('q')
  const [sort, setSort]   = useQueryParam('sort', 'newest')

  return <input value={query} onChange={e => setQuery(e.target.value)} />
}
replace vs push: 검색어 입력처럼 히스토리가 쌓이면 안 되는 경우 replace: true를 사용하세요. 필터 변경처럼 뒤로가기로 돌아와야 하면 기본값(push)을 사용하세요.

5. URL에 상태 저장하기 (Storing State in URL)

어떤 상태를 URL에 넣어야 할까? (What State Belongs in the URL?)

✅ URL에 넣어야 하는 것

  • 검색 키워드 (?q=react)
  • 필터 조건 (?status=active)
  • 정렬 기준 (?sort=price&order=asc)
  • 페이지 번호 (?page=3)
  • 선택된 탭/뷰 (?tab=settings)
  • 모달/다이얼로그 ID (?modal=invite)
  • 날짜 범위 (?from=2024-01&to=2024-03)

❌ URL에 넣지 말아야 하는 것

  • 민감 정보 (토큰, 비밀번호)
  • 임시 UI 상태 (hover, focus)
  • 매우 복잡한 객체 (너무 길어짐)
  • 자주 바뀌는 값 (스크롤 위치)
  • 인증 세션 정보

복잡한 상태의 직렬화 (Serializing Complex State)

// 여러 필터를 하나의 URL로 관리
interface FilterState {
  categories: string[]
  priceRange: [number, number]
  inStock: boolean
}

function useFilterState() {
  const [searchParams, setSearchParams] = useSearchParams()

  const filters: FilterState = {
    // 배열: ?cat=shoes&cat=bags (반복)
    categories: searchParams.getAll('cat'),
    // 범위: ?minPrice=10000&maxPrice=50000
    priceRange: [
      Number(searchParams.get('minPrice') ?? '0'),
      Number(searchParams.get('maxPrice') ?? '999999'),
    ],
    inStock: searchParams.get('inStock') === 'true',
  }

  const setFilters = (newFilters: FilterState) => {
    setSearchParams({
      // 배열은 여러 번 append
      ...Object.fromEntries(
        newFilters.categories.map(c => ['cat', c])
      ),
      minPrice: String(newFilters.priceRange[0]),
      maxPrice: String(newFilters.priceRange[1]),
      ...(newFilters.inStock ? { inStock: 'true' } : {}),
    })
  }

  return { filters, setFilters }
}

nuqs 라이브러리 (nuqs Library)

복잡한 URL 상태 관리에는 nuqs 라이브러리를 추천합니다. 타입 안전한 URL 상태 관리를 제공합니다.

npm install nuqs

function ProductPage() {

  const [tags, setTags]           = useQueryState('tags', parseAsArrayOf(parseAsString))

}

6. History API와 라우터 동작 원리 (History API Internals)

브라우저의 History API는 URL을 변경하면서도 페이지 새로고침을 하지 않는 핵심 기술입니다. React Router는 이 위에 구축되어 있습니다.

사용자 클릭 or navigate()
→
history.pushState()
→
URL 변경
→
React Router 감지
→
컴포넌트 리렌더

주요 History 메서드 (Key History Methods)

// 히스토리 스택에 새 항목 추가 (뒤로가기 가능)
history.pushState(state, title, url)

// 현재 항목 교체 (뒤로가기 불가)
history.replaceState(state, title, url)

// 앞/뒤 이동
history.go(-1)  // 뒤로
history.go(1)   // 앞으로

// React Router에서 state 전달 (URL에 표시 안 됨)
navigate('/order-complete', {
  state: { orderId: 'abc123', total: 29000 }
})

// 받는 쪽
import { useLocation } from 'react-router-dom'
const location = useLocation()
const { orderId } = location.state ?? {}
location.state 주의: 히스토리 state는 새로고침하면 사라집니다. 공유 가능한 데이터는 반드시 URL에 명시적으로 포함해야 합니다.

7. 중첩 라우트 (Nested Routes / Layouts)

중첩 라우트를 사용하면 공통 레이아웃을 유지하면서 하위 콘텐츠만 교체할 수 있습니다. 대시보드처럼 사이드바는 고정하고 메인 영역만 바뀌는 패턴에 이상적입니다. 

// App.tsx — 중첩 라우트 구성
<Routes>
  {/* 공통 레이아웃 */}
  <Route path="/" element={<RootLayout />}>
    <Route index            element={<HomePage />} />
    <Route path="dashboard" element={<DashboardLayout />}>
      <Route index             element={<DashboardHome />} />
      <Route path="analytics"  element={<AnalyticsPage />} />
      <Route path="settings"   element={<SettingsPage />} />
    </Route>
  </Route>
</Routes>

// RootLayout.tsx — 자식 라우트가 렌더될 위치를 Outlet으로 지정
import { Outlet } from 'react-router-dom'

function RootLayout() {
  return (
    <div>
      <Header />          {/* 항상 보임 */}
      <Outlet />         {/* 자식 라우트 컴포넌트가 여기에 렌더 */}
      <Footer />          {/* 항상 보임 */}
    </div>
  )
}

8. 고급 패턴 (Advanced Patterns)

8-1. 모달을 URL로 관리 (URL-based Modals)

모달을 URL에 연결하면 모달 열린 상태로 링크 공유가 가능하고, 뒤로가기로 모달을 닫을 수 있습니다. Instagram의 사진 상세보기와 같은 패턴입니다. 

// 방법 1: 쿼리스트링으로 모달 상태 관리
function UserListPage() {
  const [searchParams, setSearchParams] = useSearchParams()
  const modalUserId = searchParams.get('modal')

  return (
    <div>
      {users.map(user => (
        <button key={user.id}
          onClick={() => setSearchParams({ modal: user.id })}>
          {user.name}
        </button>
      ))}

      {modalUserId && (
        <Modal onClose={() => setSearchParams({})}>
          <UserDetail userId={modalUserId} />
        </Modal>
      )}
    </div>
  )
}
// URL: /users?modal=42 → 사용자 42번 상세 모달 열림

8-2. 코드 스플리팅과 라우트 (Code Splitting)

import { lazy, Suspense } from 'react'

// 라우트별로 번들을 분리 (초기 로드 성능 향상)
const DashboardPage = lazy(() => import('./pages/DashboardPage'))
const SettingsPage  = lazy(() => import('./pages/SettingsPage'))

function App() {
  return (
    <Suspense fallback={<div>로딩 중...</div>}>
      <Routes>
        <Route path="/dashboard" element={<DashboardPage />} />
        <Route path="/settings"  element={<SettingsPage />} />
      </Routes>
    </Suspense>
  )
}

8-3. 인증 보호 라우트 (Protected Routes)

function ProtectedRoute({ children }: { children: ReactNode }) {
  const { isAuthenticated } = useAuth()
  const location = useLocation()

  if (!isAuthenticated) {
    // 로그인 후 원래 페이지로 돌아오도록 현재 경로를 state에 저장
    return <Navigate to="/login" state={{ from: location }} replace />
  }

  return children
}

// 로그인 후 리다이렉트
function LoginPage() {
  const navigate = useNavigate()
  const location = useLocation()
  const from = location.state?.from?.pathname ?? '/'

  const handleLogin = async () => {
    await login()
    navigate(from, { replace: true }) // 원래 페이지로 복귀
  }

  return <button onClick={handleLogin}>로그인</button>
}

// 라우트 구성
<Route path="/dashboard" element={
  <ProtectedRoute><DashboardPage /></ProtectedRoute>
} />

Next.js App Router를 사용하는 경우, @slot 패턴(Parallel Routes)과 (..) 패턴(Intercepting Routes)으로 Instagram 피드 + 모달 동시 표시 같은 복잡한 UI를 구현할 수 있습니다.

8-5. URL 공유 시 상태 복원 (State Restoration from URL)

// URL에서 초기 상태를 읽어 컴포넌트 초기화
function SearchPage() {
  const [searchParams] = useSearchParams()

  // URL → 상태 초기값으로 활용
  const [filters, setFilters] = useState(() => ({
    query:    searchParams.get('q')      ?? '',
    category: searchParams.get('cat')    ?? 'all',
    page:     Number(searchParams.get('page') ?? '1'),
  }))

  // 상태 변경 시 URL에 동기화
  const [,setSearchParams] = useSearchParams()

  useEffect(() => {
    setSearchParams({
      ...(filters.query    ? { q: filters.query }       : {}),
      ...(filters.category !== 'all' ? { cat: filters.category } : {}),
      ...(filters.page     !== 1     ? { page: String(filters.page) } : {}),
    }, { replace: true })
  }, [filters])
}

9. 서버 설정 (Server Configuration for BrowserRouter)

BrowserRouter를 사용할 때, 사용자가 /users/42를 직접 입력하거나 새로고침하면 서버가 해당 경로에서 index.html을 반환해야 합니다.

Nginx

server {
    listen 80;
    root /var/www/html;
    index index.html;

    location / {
        # 파일이 없으면 index.html로 fallback
        try_files $uri $uri/ /index.html;
    }
}

Apache (.htaccess)

Options -MultiViews
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^ index.html [QSA,L]

Vite / CRA 개발 서버

// vite.config.ts — 개발 서버에서는 자동 처리됨
export default {
  server: {
    historyApiFallback: true, // 기본 활성화
  }
}

Vercel / Netlify

// vercel.json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}

// netlify.toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

  • ☐ 서버에서 모든 경로가 index.html을 반환하도록 설정
  • ☐ 404 페이지 <Route path="*"> 추가

URL 설계

  • ☐ 리소스 식별에는 URL 파라미터 (/users/:id) 사용
  • ☐ 필터/정렬/페이지는 쿼리스트링 (?sort=price) 사용
  • ☐ 모달/다이얼로그 상태도 URL에 반영 (?modal=invite)
  • ☐ 불필요한 기본값은 URL에서 제거 (깔끔한 URL 유지)
  • ☐ 민감한 정보는 절대 URL에 포함하지 않기

사용자 경험

  • ☐ 새로고침 후 동일한 화면이 보이는지 확인
  • ☐ 뒤로가기/앞으로가기 정상 동작 확인
  • ☐ URL 직접 입력 시 정상 렌더 확인
  • ☐ 링크 공유 후 받은 사람이 동일한 상태 확인
  • ☐ 라우트 전환 시 로딩 상태 처리

성능 최적화

  • ☐ 라우트별 코드 스플리팅 (React.lazy) 적용
  • ☐ 빠른 네비게이션을 위한 링크 프리패칭 고려
  • ☐ 검색 입력에 replace: true 사용 (히스토리 오염 방지)
